# 前言

## 这是一本关于算力的书

关于 AI 的书很多，讲模型、讲算法、讲框架。但当一个省决定把一千张 GPU 落成一栋楼、并且要让它**稳定对外提供算力**时，真正卡住项目的往往不是模型——**是交付**。

本书写的就是这一段：**从"要建多少卡"，到"这些卡能不能稳定跑出利用率"。**

一句话概括立场：**在 AI 时代，算力是被"交付"出来的，不是被"买"回来的。**

- 买回来的是一批设备：GPU、服务器、交换机、光模块、线缆；
- 交付出来的是一种能力：一个能被调度、能被压测、能被排障、能被扩容的集群。

这两者之间的距离，就是本书的全部内容。而在这段距离里，**网络是出现频率最高、也最容易被低估的那一环**——它不产生算力，但它决定了已经买到的算力能不能被用出来。

**所以本书的主语是"智算中心"，不是"交换机"。** 网络在这里不是主角，而是那个决定主角能发挥几成的东西。

## 算力利用率是怎么在网络层掉下去的

评价一个智算中心，看的从来不是"装了多少卡"，而是"这些卡能跑出多少有效算力"：

```
有效算力 ≈ 卡数 × 单卡算力 × 通信效率 × 可用率
```

乘号后面这三项，没有一项由 GPU 决定——它们全部由智算中心的**架构、物理层、协议参数、存储与运维体系**决定。下面这张表就是"算力是怎么掉下去的"逐环节清单，它同时也是本书的目录。

| 算力流失的环节 | 典型表现 | 对应章节 |
|---|---|---|
| 集群规模与网络需求测算 | 不知道自己的卡数需要什么样的网 | 第 1、2 章 |
| 拓扑与端口配比 | 集合通信 busbw 掉 20–50%，AllToAll 直接顶墙 | 第 3 章 |
| 物理层（端面、极性、模块批次） | 偶发误码、偶发掉速，且不可复现 | 第 4、5 章 |
| 协议与无损参数（PFC / ECN / headroom） | 拥塞时暂停扩散，整个集群卡住 | 第 6–9 章 |
| 存储与 Checkpoint | 训练被 I/O 屏障拖住，卡在等数据 | 第 10 章 |
| 辅助平面（带外、时间同步、控制面） | 故障时无法判断"谁先坏"，只能瞎猜 | 第 11 章 |
| 施工与缆长 | 返工、停工、交期，全都落在工期上 | 第 12 章 |
| 压测、调优与可观测性 | 上线后 90% 的时间花在监控和变更上 | 第 13–15 章 |
| 预算、招投标与交付管理 | 口径不统一，比价变成猜谜，验收变成扯皮 | 第 16、17 章 |
| 技术演进 | 今天的最优解，三年后要换什么 | 第 18 章 |

**这本书想解决的，就是上面这十行问题。**

它们没有标准答案，但都有**可复现的判断过程**。本书的做法是：把一条真实交付过的链路——**需求、选型、采购、施工、组网、压测、优化、调度**——完整摊开，让后来者能照着走一遍，而不是从头踩一遍。

## 一条贯穿全书的主线案例

本书不讲空对空的架构。全书所有算术、参数、报价、验收口径，都来自**同一个真实交付项目**：

> **某省运营商自用智算中心**
> 终态 **128 台 H100 训练服务器 / 1024 张 GPU**，内部代号 **HC-1024**（按终态卡数命名）。
> 它不是一次性建成的，而是**三期滚动**建成的——这一点贯穿全书，因为"滚动扩容如何在不动现网的前提下做加法"，本身就是智算中心工程最核心的约束之一。

| 分期 | 服务器 | GPU 卡数 | 算力 Leaf | 算力 Spine | 本期服务器到货 |
|---|---|---|---|---|---|
| 一期 | 32 台 | 256 | 8（每轨 1 台） | 8 | 32 台 |
| 二期 | 96 台 | 768 | 16（每轨 2 台） | 8 | +64 台 |
| 三期 | 128 台 | 1024 | 16（每轨 2 台） | 16 | +32 台 |
| 四期（预留） | 256 台 | 2048 | 32（每轨 4 台） | 16 | — |

**设计原则只有一句话：按终态一次规划、按分期逐步填充，扩容只做「纯加法」。**

单台服务器的网络配置如下——后面每一章的算术都从这张表长出来：

| 接口 | 数量 | 形态 | 用途 |
|---|---|---|---|
| 算力网卡 | **8 × 400G** | OSFP | 每张 GPU 配一个专用 400G 口，各自独立成「轨」 |
| 存储网卡 | 2 × 100G | QSFP56 | 双平面冗余，独立存储专网 |
| 业务网卡 | 2 × 25G | SFP28 | 双上联 |
| 带外管理 | 1 × 1G | RJ45 | BMC，物理独立 |

> **★ 一个必须先接受的关键事实：算力网卡是「每卡一口」，不是「每节点两口」。**
> 这一条决定了后面所有的拓扑算术——8 张网卡各自独立成轨，轨道归属由**卡号**唯一确定，与服务器插在哪个机柜无关。它也是"一千张卡的网络为什么不能按传统数据中心的思路设计"这个问题的起点。

**你不需要有同样的规模。** 把上表的 128 换成你自己的张数，第 3 章的端口配比六步法和附录 B 的计算表可以直接重算一遍，结论同样成立。

## 数据来源与口径约定

书中每一个关键数字都带来源标记，不标来源的数字一律视为无依据：

| 标记 | 含义 |
|---|---|
| `【实测】` | 现场真实记录（压测日志、验收报告、配置导出、现场计数） |
| `【设计】` | 由方案确定的设计取值，**不是**实测值 |
| `【推算】` | 由公式推导，正文给出完整算式 |
| `【估算】` | 经验估算，必要时附误差范围（如 `【估算 ±30%】`） |
| `【原厂】` | 厂商文档或 Datasheet 标称值 |
| `【行业公开】` | 标准、白皮书等公开资料 |
| `【市场参考】` | 2026 年三季度该案例的含税报价 |
| `【待实测】` | 现场未采集到、书中不作编造的缺口（清单见附录 F.9） |

**单位约定**（这是全书第一个坑，也是第 1 章开篇那条验收条款栽的地方）：

- 链路速率一律用 **bit**：`Gb/s`、`Tb/s`、`400G`；
- 容量与数据量一律用 **Byte**：`GB`、`TB`、`GiB`。
- 两者之间隔着一个 **8**。看到这两个单位出现在同一句话里，先停下来检查。

**关于诚实边界**：本书有多处现场数据因故未能采集（例如单节点 8×400G 满载的 nccl-tests 全量基线、96 台全规模实测曲线、PFC/ECN 具体参数值）。这些位置在正文中一律标注「**待实测**」，不用推算值冒充实测值。**宁可留白，不编数字**——这本身也是这本书想传递的工程习惯。

## 关于脱敏

本书来自真实项目，但**不是一份可以反推出现场身份的文件**。处理原则如下：

| 保留 | 隐去 |
|---|---|
| 设备型号与规格（CE9866-128DQ、ConnectX-7、H100 等） | 客户单位名称、承建方与集成商名称 |
| 设备含税单价、施工与服务单价 | 项目合同总额、付款节点、质保金额、毛利 |
| 合同条款的**原文口径**（这是争议复盘的关键） | 合同条款编号、签署双方 |
| 私有网段规划（教学价值核心） | 公网 IP、真实域名、机房地址 |
| 现场故障与争议的处理过程 | 人员姓名、门牌号、设备序列号 |

文中一律使用「某省运营商智算中心」「本案例」「承建方」「服务器供货方」这类角色化称呼。**设备价格保留是有意的**——比例关系比绝对数字更有参考价值，而隐去单价会让整本书失去一半的实用性。

## 怎么读这本书

**每章六段骨架**（模块一至三的二级标题即段名；模块四至六主题跨度大，按主题组织，但要素齐全）：

```
01 工程问题  →  从一个真实的争议、故障或取舍切入，先把问题立住
02 最小必要原理  →  够用就停，不展开推导，只给能支撑决策的那部分
03 选型对比  →  把可选项摊在桌上比，给判断依据而不是给结论
04 实测与踩坑  →  现场发生了什么、为什么、怎么复现、怎么防
05 现场检查清单  →  可打印带去机房的勾选项
06 成本与工期影响  →  这个选择在钱和进度上意味着什么
```

**三条推荐路径**：

- **设计与选型**（架构师、网络规划）：第 1–3 章连读 → 第 6–9 章选阵营 → 附录 B 算你自己的端口账。
- **现场交付**（施工、联调、运维）：第 4–5 章物理层 → 第 12–15 章施工压测调优 → 附录 A、C、E 带去机房。
- **预算与采购**（项目经理、商务）：第 16–17 章 → 附录 B 与第 7 章成本锚点 → 回头补第 3 章端口算术。

**章节可跳读，但第 1、2、3 章建议连读**：它们分别回答「一千张卡为什么难」「智算中心为什么必须分层」「端口账怎么算」，是后面所有章节的地基。
