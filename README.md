## 这本书解决什么问题

智算中心的网络，和传统数据中心网络不是一回事。传统数据中心是「南北向为主、收敛比 3:1 到 5:1、丢包重传无所谓」，
而大模型训练是「东西向 AllReduce 为主、要求 1:1 无收敛、对丢包和抖动极度敏感」。
把传统数据中心的经验直接搬过来，几乎一定会踩坑。

本书不做科普，假定的读者已经知道什么是 IP 地址、什么是交换机。全书只回答三个问题：

1. **钱花在哪**——拓扑怎么设计、收敛比怎么定、哪些物料最容易漏算；
2. **坑在哪**——选型、施工、组网、调优各阶段的真实事故与根因；
3. **怎么验证**——每一层给出可复现的算式和可打印带到机房的检查清单。

**主读者**：智算中心项目技术负责人 / 网络架构师；参与选型与采购的技术采购；从传统运维转向 AI Infra 的工程师。

**明确不写给**：零基础读者。

## 主线案例

全书用**同一个案例**贯穿始终，任何一章里引用的数字都能在附录 F 找到出处，形成一条可交叉验证的「数据锚点链」。

| 项 | 参数 |
|---|---|
| 场景 | 某省运营商自用智算中心 |
| 规模 | 128 台 GPU 服务器 / 1024 卡（项目代号 HC-1024） |
| 分期 | 一期 32 台 → 二期 96 台 → 三期 128 台，四期预留 256 台 |
| 算力网 | 单端口 400 Gb/s，Leaf-Spine 两层 CLOS，收敛比 1:1 |
| 存储网 | 物理独立组网，3 节点前端 |
| 平面 | 算力 / 存储 / 带内 / 带外 / 控制同步，五平面物理隔离 |

### 脱敏声明

案例源自真实交付项目，已按下列原则脱敏，**不影响工程结论的可复用性**：

- **隐去**：客户名、承建方名、供货方名、人员姓名、机房地址、合同条款编号；
- **保留**：设备型号、私有网段规划、**设备与施工单价**——这些是本书的实用价值所在；
- **改为量级**：项目合同总额、付款节点、质保金额、毛利等商务信息。

书中数据均标注来源口径（`【实测】/【原厂】/【设计】/【推算】/【估算】/【报价】/【行业公开】`）。
尚未取得实测数据的指标一律显式标注为**待实测**，并给出推理参考区间与推算依据，绝不编造。
